# 01.01 Local service topology

Antigravity IDE -> dedicated model proxy 127.0.0.1:51002 -> local OpenAI-compatible custom endpoint -> OmniRoute 127.0.0.1:20128/v1 -> connected providers.

Antigravity Desktop -> model proxy 127.0.0.1:50999 -> OmniRoute 127.0.0.1:20128/v1.

CodeMap / Voice-PC-Agent / Obsidian / Voice Assistant / future clients -> directly call OmniRoute local OpenAI-compatible endpoint using distinct client keys and stable model names / Combos.

Browser model-inventory companion -> 127.0.0.1:20129 -> read-only catalog/provider API calls on 20128, plus explicit user-triggered sync or per-model test.

## Ports
| Port | Service | Network binding | Notes |
|---|---|---|---|
| 20128 | OmniRoute inference and dashboard | 127.0.0.1 | Use /v1 for compatible API; /dashboard is NOT the inference endpoint |
| 20129 | Companion Model Inventory | 127.0.0.1 | Separate process and browser page, not built into OmniRoute |
| 50999 | Desktop patched model manager | 127.0.0.1 | Standalone Electron patch |
| 51002 | IDE custom-model proxy | 127.0.0.1 | Uses IDE managed setting, not patched IDE source |
| 5050 | Edge-TTS voice dashboard | local tool, separate | Outside OmniRoute |
| 8765 | Voice-PC-Agent backend default | local app, separate | Confirm live status before relying on it |

## Routing rules
Model ID must correspond to a real OmniRoute provider model, saved Combo alias, or supported virtual auto route. A dashboard URL is not a valid inference endpoint. Model fallback is not equivalent to agent conversation/state recovery; the calling client must preserve context and tool state.
