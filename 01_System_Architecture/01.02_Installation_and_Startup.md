# 01.02 Installation, startup and shutdown

## Versions
- OmniRoute: 3.8.50 (npm-installed, Windows Node.js runtime).
- Node.js prerequisite observed: v24.14.1; Git v2.55.0.windows.3.
- Antigravity IDE: 2.5.5, VSCode OSS 1.107.0 (user setup).
- Standalone Antigravity Desktop: 2.24.0 at patch completion.

## One-click start
Double-click the Desktop shortcut named **START OmniRoute + Both Dashboards.cmd**. The supporting PowerShell file lives in the Model Inventory companion directory.

Intended behavior:
1. Detect whether OmniRoute is already listening on 20128.
2. Only when absent, start using the real User-scoped DATA_DIR and force OMNIROUTE_SERVER_HOST=127.0.0.1.
3. Detect whether inventory is listening on 20129, start if needed.
4. Open both browser dashboards.

Existing listeners remain untouched. The launcher was tested when both services were already running. Re-test the cold-start path before calling it fully validated.

## Critical historical pitfall
On 2026-10-19, an OmniRoute restart command run without the correct DATA_DIR attempted to start a second instance pointing to the stale user-profile DB and binding 0.0.0.0 without API-key enforcement. That instance was stopped immediately. Never run a generic restart/start command without explicitly checking the E: DATA_DIR and the loopback bind. Do not delete the stale DB while credentials/encryption origin remains uncertain.

## Desktop/IDE proxies
Antigravity IDE is launched with the managed integration's IDE launcher; the default shortcut may not initialize its proxy. Desktop patched runtime uses its own port and recovery backups. Do not modify Electron asar or executable while Antigravity processes are open.

## Shutdown
Use supported commands after selecting the correct data directory. Close critical clients gracefully and check listeners after shutdown; do not force-close during long agent operations.
