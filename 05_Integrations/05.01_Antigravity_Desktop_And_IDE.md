# 05.01 Antigravity Desktop 2.24.0 and IDE 2.5.5

## Objective
Use the original Antigravity Agent Manager and model picker with OmniRoute-hosted models via a third-party integration (not a Google-supported native external-key feature).

## Components
- Third-party repository: vahapogut/antigravity-add-model, locally cloned and built.
- Desktop: standalone Electron app.asar patch plus a separate language-server/endpoint modification, proxied at 50999.
- IDE: IDE adapter uses managed jetski.cloudCodeUrl setting and a proxy on 51002, rather than patching IDE application source.
- Both were checked for compatibility before applying; installers preserved original settings/binaries in backups.
- Original model manager path uses /_addon/ on respective loopback proxy.

## History
IDE preflight passed for 2.5.5; proxy started; IDE launched. Desktop preflight passed; after safe closure of a headless process, standalone patch installed on version 2.24.0 and its proxy became active.

## Native model configuration
Use Provider=Custom endpoint, API format=OpenAI-compatible, API base=http://127.0.0.1:20128/v1, dedicated Antigravity client API key, exact OmniRoute model/Combo/virtual alias, descriptive display/configuration name. Do NOT use /dashboard/providers as an API URL.

## Advanced parameter baseline
Provider default reasoning; blank thinking budget until model verified; inherit compaction effort; leave maximum output/context blank until per-model capabilities are confirmed; IDE compaction threshold default; retries ~2; 120 s initial request timeout; TLS verification on; no arbitrary headers unless provider requires them.

## Quality caveat
The auto/best-coding model picker name does not prove upstream model identity or coding ability. Codex scored a past Stratum repair 3/10; see 10.02 for reproducible defects and verification requirements. The process may have involved model switching or compression, but no causal attribution has been proven.

## Recovery
Use the patch project documented IDE restore and desktop repair/restore workflow; keep backups and never modify binaries while agents/processes are active. Updates can invalidate patches. Re-check compatibility after each Antigravity version update.

## Remaining
Verify real code-edit/tool-call flows, upstream model identity in logs, user quotas, 429 fallback and correct context replay through each proxy.
