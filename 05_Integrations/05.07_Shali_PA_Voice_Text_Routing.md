# Shali P.A. — Verified Voice and Text Model Routing

**Updated:** 2026-10-20. **Status:** Active local configuration on OmniRoute 3.8.52 and Shali P.A.

## Architecture
Shali P.A. currently follows a microphone/transcription → text generation or summary → TTS → playback pipeline. The TTS speaker is **not controlled by OmniRoute's text-model Combo**. The system also has browser and desktop content summarization tools.

### Spoken output / TTS hierarchy
1. **Gemini 3.8 Flash TTS** — `gemini-3.8-flash-tts`; configured primary, voice `Sulafat`, Pakistani Urdu pronunciation instructions.
2. **Gemini 3.8 Flash-Lite TTS** — `gemini-3.8-flash-lite-tts`; attempted only when primary Gemini synthesis returns an error and fallback is enabled.
3. **Edge Neural TTS** — `ur-PK-UzmaNeural` for Urdu; attempted when both Gemini speech stages fail.

The speech engine returns a visible warning when speech changes to a fallback. A cached primary voice response can be reused within the local cache window.

### Everyday text answering and summaries
The existing `Voice-Assistant` client key remains restricted. The same historical `obsidian-voice` Combo name was retained to preserve integrations, with **fallback** strategy and this ordering:

1. `gemini/gemini-3-flash-preview` (provider Gemini, saved Combo ID model `gemini-3-flash-preview`).
2. `groq/qwen/qwen3.8-27b` (actual provider model `qwen/qwen3.8-27b`).
3. `groq/openai/gpt-oss-120b` (actual provider model `openai/gpt-oss-120b`).
4. Gemini 2.5 Flash.
5. Gemini 3.1 Flash Lite.
6. Gemini 2.5 Flash Lite.

Both Groq models returned actual HTTP 200 completions under the Voice-Assistant key. The previous Gemini fallback members were preserved. Newer Gemini 3.8 and 3.6 **text** routes returned HTTP 400 through OmniRoute during testing and were not promoted. That result does not affect direct Gemini **TTS** access.

### Long-document and high-reasoning text path
When a single text-summary source is at least **12,000 characters**, Shali's briefing engine first requests `groq/openai/gpt-oss-120b` using the dedicated Voice-Assistant key. If this returns an error, an empty response, or an incomplete reply, it retries using `obsidian-voice` and its diversified fallback Combo. Short replies stay on the standard Combo. Neither path changes spoken voice selection.

## Limits and safety
- The synthesized voice's naturalness and Urdu accent still require owner listening acceptance; a silent API test cannot prove perceptual quality.
- Actual low-latency full-duplex voice-to-voice via **Gemini 3.8 Live** is **not implemented** by this TTS fallback change. It would need a separate realtime audio streaming client, microphone/session consent and testing.
- Google pricing shows eligible free-tier access for Gemini 3.8 Flash TTS, Flash-Lite TTS and Live, but free quota is finite. Avoid automatic paid-mode billing; account/provider hard-stop must be verified.
- Free-tier Google API data-handling terms can differ from paid terms; do not send excluded private files, screenshots, memory or credentials without approval.
- No user documents or real conversations were sent during model tests. No public doc contains API keys.
- Speech-to-speech fallback only operates while the local runtime is online. Mobile/off-PC availability requires separate deployment.
