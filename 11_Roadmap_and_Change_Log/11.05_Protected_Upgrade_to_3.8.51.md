## Critical 163 migration collision
The old active database marked version 163 as `model_capabilities`, but 3.8.51's migration 163 expects `radar_feed_cache_generated_at`. The released SQL adds `radar_feed_cache.generated_at TEXT DEFAULT NULL`. With the server cleanly stopped, that missing column was added to match released schema; integrity passed afterward. The 3.8.51 boot then reconciled migration records and applied through version **196**.

## Rollback
Do not use blind downgrade on the migrated live DB. Stop server with explicit E: DATA_DIR, back up the current migrated DB, then restore the pre-upgrade 3.8.50 SQLite snapshot along with the pinned 3.8.50 npm package and verified package env only if needed. Confirm all five keys and seven Combos and loopback binding again. A schema-only backward edit is not a safe rollback.
