# 04.04 Client usage map and observability

OmniRoute knows API keys and model requests, but cannot always infer the true external desktop application if the same key is reused by different apps or unauthenticated requests arrive.

## Attribution checklist
- Give every client a unique dedicated key and a stable alias or Combo.
- Assign a descriptive, non-sensitive name and optional client identifier header if supported; never send secrets in metadata fields.
- Inspect API Manager usage by key, Traffic Inspector, request error/success, provider chosen and fallback transition.
- Review recorded last-used timestamps; absence of usage is not proof no dependency exists.
- Enable safe diagnostic collection only (no full prompt retention unless explicitly needed and secured).

## Key usage evidence 2026-10-19
- Antigravity key used recently; existing CLI Auto-Key last-used record dates to earlier in October.
- Voice-Assistant's last-used field was unset in key table even though Obsidian/Voice integration was believed to work; app may call a different key/route or usage source may differ.
- CodeMap and Voice-PC-Agent dedicated new keys had no recorded last-used timestamp when examined; auth/inference test is still pending.

## Security
Never store bearer values in shared API docs or Git history. Full client identifiers, key hashes, GUIDs and secrets are omitted from public inventory files.
