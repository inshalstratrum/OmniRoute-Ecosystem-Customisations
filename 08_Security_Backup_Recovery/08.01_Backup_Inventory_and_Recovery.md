## Backup requirements
Use SQLite online backup API, not uncoordinated file copy of a WAL-mode live store. Validate PRAGMA integrity_check on the backup. Record active DATA_DIR and the last known good service state. Keep SQLite, its encryption configuration and any credential recovery material **outside Git**.

## Recovery outline
1. Stop new routing/agent jobs and diagnose failure scope.
2. Verify localhost-only binding and correct E: DATA_DIR.
3. Snapshot current failing state, preserve user projects.
4. Restore the identified verified SQLite backup using correct SQLite procedure while server is fully stopped.
5. Restore program/app files or config only if they are in the failure scope.
6. Re-start with pinned DATA_DIR, test dashboard, key auth, provider health, saved Combos and request flow.
7. Record the incident, cause and post-recovery testing in the change log.

Do not rotate, revoke or delete all keys as a general troubleshooting shortcut.
