# 08.02 Secrets and GitHub publication gate

## NEVER publish
- Active API keys, bearer tokens, key hashes, passwords, session cookies, signed URLs, provider secrets.
- Original OmniRoute SQLite DB, .env, key-export files, credential recovery scripts containing key material.
- Personal synchronization-drive Credentials.md.
- Logs or request captures containing raw prompts/screenshots, full personal filesystem paths or email addresses.
- Private machine paths file with suffix .local.md.

## Protections
The root .gitignore excludes typical secrets, local-only docs, backups, databases, logs and binaries. Gitignore is not proof of safety: always scan staged file contents AND Git history. An ignored secret previously committed must be rotated and history handled separately.

## Recommended commands prior to commit
- git status --short
- git diff --cached --stat
- git diff --cached --check
- git check-ignore -v path/to/private/file
- Run a reputable secret scanner against staged changes and history (review locally; don't print keys).
- Confirm there are no direct paths to personal synced Credentials.md included in staged files (local path registry is ignored).
- Review autogenerated snapshots before publishing; sanitize connection labels, personal IDs and application metadata.

## Key reveal
ALLOW_API_KEY_REVEAL=true is currently a conscious temporary usability risk. Management auth + loopback are safeguards, not a reason to leave secrets exposed. Turn flag off after securely recording keys and verify 403 when authenticated.
