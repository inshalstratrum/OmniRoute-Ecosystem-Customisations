# 08.04 Encrypting Google Drive-synced credential documents

## Current situation (2026-10-19)
The separate `Credentials/OmniRoute_API.md` has been manually populated with all five current OmniRoute API keys. The five values were verified against active database records **without printing them**. This means the earlier "NOT COMPLETED" vault status was outdated and has been corrected.

**Important:** Google Drive synchronization of an ordinary plaintext Markdown note is NOT equivalent to encrypted private storage. Windows NTFS file ACLs or a password-based Explorer folder lock do not automatically encrypt bytes already uploaded to Google Drive. Sharing controls help but do not give client-side encryption.

## Recommended routes
1. **Cryptomator**: strongest fit for mixed credential files (.md, .env, attachments). Place its encrypted vault within the Google Drive synced directory, put sensitive files in the unlocked virtual drive, and verify they arrive as encrypted objects. Carefully check integration because scripts cannot read the original plaintext file path while vault is locked.
2. **Meld Encrypt (Obsidian community plugin)**: encrypt selected notes or whole Markdown notes. Its maintainers explicitly say the encryption implementation has not received an independent security audit. Decrypted text stays in Obsidian memory.
3. **Folder Encrypt plugin**: encrypt many Markdown notes within Obsidian, including selected file names; test on a copied folder and verify link behavior and supported platforms. It does **not** encrypt arbitrary non-Markdown files.
4. If replacing the entire sync workflow, evaluate an Obsidian end-to-end-encrypted Google Drive sync plugin. Avoid having two sync engines simultaneously write the same vault.

## Migration checks
- [ ] Make an offline copy of the existing plaintext credential file, protected locally.
- [ ] Confirm Google Drive and Obsidian sync are paused for the relevant folder before migrating.
- [ ] Choose a strong unique passphrase, store the recovery material **outside that same vault**.
- [ ] Test encryption/decryption using a dummy note.
- [ ] Move/copy real secrets into encrypted container, then reopen on the PC and on another device if used.
- [ ] Ensure cloud copy contains ciphertext only. Note that previously synced plaintext versions may exist in Google Drive version history or Trash.
- [ ] Audit and remove historical plaintext copies where safe; consider rotating sensitive keys if cloud disclosure was possible.
- [ ] Update scripts relying on the old credential path and document unlock requirements.
- [ ] Never commit the unencrypted content or encrypted vault password to GitHub.
