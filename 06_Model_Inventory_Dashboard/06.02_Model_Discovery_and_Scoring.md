# 06.02 Discovery and controlled scoring workflow

1. Verify server and management sign-in.
2. Refresh unified catalog; distinguish catalog records from active connection candidates.
3. If selected provider has a supported discovery API, trigger Sync selected provider explicitly (merges model IDs).
4. Filter for verified zero-cost hard-stop, refilling quota, supported context/output limits and requested modalities.
5. Test one model at a time; each test is a genuine request and can consume quota or trial credit.
6. Record success, 429/401/502 failures, latency, streamed/tool-call behavior, context fidelity and chosen upstream connection.
7. Rank by task-specific quality and stability, not names (best/pro/frontier) alone.
8. Assemble draft priority order; apply to a saved Combo only after reviewing actual dependants, quota and billing.
9. Verify fallback using fault injection or controlled provider unavailability without draining scarce credit.

## Suggested fields
Provider / connection class / model ID / true free type / hard-stop evidence / remaining quota / tools / vision / context / max output / task score / last good test / last 429 / fallback rank / reserve status / privacy and ToS caveat.

Do not use experimental prompts containing personal data or secret URLs.
