# 06.01 Separate Model Inventory and Fallback Planner

## Status
The custom dashboard is currently a **separate localhost companion** on port 20129, not a native /dashboard/* route in the OmniRoute application.

## Local source
The main files are server.mjs (loopback-only bridge), index.html (UI), app.js (logic), Start-Inventory.ps1 (launcher), and README.md in the Model Inventory working directory outside this vault. Do not duplicate the source in this documentation vault without code review.

## Available features
- Live catalog read from existing OmniRoute management API.
- Connected provider groups, IDs, free-status flag, context/output metadata, vision heuristic, search/sort/filter.
- Individual generation test on explicit user confirmation. Tests can consume quota; no automatic bulk generation tests.
- Selected provider sync in merge mode. This can change imported model records but not provider credentials.
- Draft ranked fallback queue, CSV export, copy model IDs, links to original provider, Combo, quota and ranking pages.
- Session-only model test results; no centralized verified bench-score persistence.
- Fixed allowlisted forwarding routes, localhost bind, origin checks for writes. Provider credentials omitted from browser-facing connection list.

## Authentication and known limitations
The catalog endpoint returned HTTP 401 without management credentials. The bridge may require an authenticated dashboard session and cannot bypass login. A provider's inference key is not necessarily a management key. Connection-to-provider alias matching can be imperfect. A catalog entry is not proof of actual accessible/free inference.

## Desired future implementation
Native, authenticated Models workspace in OmniRoute sidebar; run discovery on demand per provider with rate limits; classify cost/ToS/one-time-vs-refillable quotas; save test history without prompts or secrets; offer preview and dry-run for applying fallback Combo changes.
