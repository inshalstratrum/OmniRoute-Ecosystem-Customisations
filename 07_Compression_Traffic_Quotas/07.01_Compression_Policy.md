# 07.01 Safe compression baseline

## Previous and current
Previously: global stacked RTK (standard) + Caveman (full), potentially over-compressing agent context.

Current saved baseline: global enabled; mode stacked; stack [session-dedup, lite(lite)]; preserveSystemPrompt=true and preserveSystemPromptMode=always; cache 15 minutes. Antigravity key compression_enabled=0. CLI Auto-Key compression_enabled=1 (not yet audited).

## Rationale
For code and tool-using agents, preserve exact file paths, line numbers, stack traces, API schemas, branch/version info, tests and unresolved-defect checklists. Repetition-only deduplication and lite format cleanup are safer initial settings than aggressive/ultra rewriting.

## Verification tasks
- Compare raw vs compressed technical prompts: file paths, JSON, terminal commands, diagnostics and user priorities must survive exactly.
- Check combined request model context size, compaction threshold and client-side summarization (a different mechanism).
- Validate correctness of tool definitions (MCP accessibility and description compression remain globally enabled).
- Consider app-specific settings: summary clients may tolerate more compression than autonomous coding agents.
- If failure, disable per-key compression first and re-test; do not edit many knobs simultaneously.
