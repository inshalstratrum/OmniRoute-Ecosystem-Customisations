# 07.02 Traffic inspector, quotas, failures and attribution

## Existing settings
- autoRefreshProviderQuota=true with interval=120 in active DB.
- quotaPreflight enabled with 2% default threshold and 20% warning.
- All 13 provider records had quota_visible=1 and rate_limit_protection=1 when audited.
- NVIDIA max_concurrent=1 to protect scarce quota.
- Global requestRetry=2 and maxRetryIntervalSec=30.
- logToolSources=true (saved).
- call_log_pipeline_enabled=0; check whether advanced inspector requires this or other pipeline features.

## Historical traffic observations (not current service promises)
- Gemini 3.1 Flash Lite had numerous successful calls and 429 rate-limit responses.
- HuggingChat model calls had repeated 502 responses; treat as untrusted fallback until retested.
- Some OpenRouter and OpenCode free labels returned 403/404/400/402. A model catalog containing an alias does not guarantee it is accessible.
- Antigravity special-provider calls recorded successes and timeouts; these are not necessarily ordinary free API terms.
- Connection-test traffic was heavy on some providers. Avoid unnecessary tests of one-time quotas.

## Recommended dashboard usage
Record per key: requested model, resolved provider+model, HTTP status, latency, retry/fallback count, quota headroom, actual output validity. Alert on 429, repeated 5xx, unexpected 402, paid cost, new provider not on allowlist, or a key used by an unexpected client.

## Privacy
Use credential redaction; do not collect signed URLs, full prompts/screenshots or authentication headers in published logs. Export aggregate counts only.
