# 03.04 Fallback quality, preserving agent context

Automatic rerouting keeps a request alive after upstream failures, but does not transfer hidden state between unrelated models. The client must replay enough prior context and preserve project artifacts.

## Minimum agent-coding fallback contract
- The client sends a complete, within-limit conversation summary: objectives, constraints, previous findings, failures, steps completed and remaining.
- Repository worktree and tracked/untracked files remain consistent. Back up and checkpoint before autonomous edits.
- Tool schema and permissions must be supported by each fallback model.
- Do not aggressively compress paths, stack traces, exact source, file diffs, regression results, JSON schemas, terminal output or user safety constraints.
- Use one lead coding agent per repair scope; avoid parallel overlapping edits unless explicitly coordinated.
- Require a verification loop: reproduce -> patch -> production-caller regression -> existing suite -> diff review -> commit/checkpoint -> re-audit.
- Compare fallback capability rather than blindly using first online model; lower-quality free candidates should handle summaries, not risky commits.
- When fallback changes the upstream model, log old/new model, cause and replay context size. Human review for model switching during stateful tool execution.

## Route acceptance
The candidate must pass: working HTTP completion, required tools/vision as applicable, long-input truncation tests, context-limit validation, error recovery, no billing, and repeatability under temporary rate limits.

No 100%-safe invisible mid-step model handoff is guaranteed by the gateway alone.
