# 02.05 — OmniRoute 3.8.52 Model Tests: Policy Blocks vs Provider Outage

Date: 2026-10-20. No secrets, authentication cookies, user prompts, or API keys recorded.

## Verified diagnosis
- OmniRoute v3.8.52 and its database were healthy. Twelve provider connections were enabled; several provider authentication tests and real generation requests succeeded.
- Native model-test API `/api/models/test` checks `hidePaidModels` and rejects models unless its shipped `FREE_MODEL_BUDGETS` classifier recognizes their **provider-native model ID**; it returns HTTP 403 `Paid model blocked while hidePaidModels is enabled`. This is a **policy rejection**, not evidence of a provider-wide blacklist.
- Our localhost companion model inventory (port 20129) passed *fully qualified* catalog IDs to the native test API as the `modelId`, causing false negatives even for known free models. The endpoint expects the provider and unprefixed model ID separately.
- OmniRoute's model lockout status endpoint reported `{"items":[]}`. The five OmniRoute client keys had zero explicitly blocked models. Successful sample generation: Gemini 3 Flash Preview; Groq GPT-OSS 120B. Direct Gemini 3.8 Flash TTS also passed a silent audio test via the Shali-PA speech engine.
- The native model dashboard, its paid guardrails, all provider credentials, and original routing Combos were **not modified**.

## Corrective work: separate localhost Model Inventory
Directory: `%USERPROFILE%\Documents\OmniRoute-Model-Inventory\`

- `app.js`, `index.html`: official free classification, clear policy-block labels, connected/refillable free default filters, disabled Test action for paid/unknown/one-time/keyless/ToS-risk models.
- `README.md`: safety constraints and run instructions.
- Regression tests: `node test-model-ids.mjs` (9 checks), `node test-safe-free-policy.mjs` (20 checks); both passed.
- Authenticated browser `GET /api/free` returned 467 catalog free-regime entries; the companion listed 361 model entries with 19 considered **eligible** for safe refillable-free tests. Eligibility does not prove a given model is currently responsive, has remaining quota, or will never change pricing.
- Companion served /models and /app.js with HTTP 200; OmniRoute API /api/health returned HTTP 200. CLI without dashboard auth correctly received 401 for management APIs.
- Original companion files were backed up in its local `backups/` directory before patching.
- At the time of this initial diagnostic, changes applied only to the companion. The native endpoints were subsequently patched and independently tested on 2026-10-21; see `11_Roadmap_and_Change_Log/11.07_Native_Free_Model_Test_Hotfix_3.8.52.md`.

## Hugging Face distinction
- OmniRoute ships **two separate connectors**: `huggingchat` (web-session cookies for HuggingChat) and `huggingface` (Hugging Face Inference Providers via user API token). A Hugging Face token is not a HuggingChat cookie; the latter may expire or fail model discovery.
- No cookie extraction or credential import was performed.
- Hugging Face currently documents approximately $0.10/month of free monthly inference credits for Free users (subject to change), not unlimited inference. Usage above free credits is not appropriate for a strictly zero-spend account; do not enable auto-pay. Official pricing: https://huggingface.co/docs/inference-providers/pricing
- Next manual setup: create a fine-grained Hugging Face user access token with inference-provider permission and paste it into the *HuggingFace* provider form in the local OmniRoute UI, not chat. Confirm billing guardrails and quota before testing.
